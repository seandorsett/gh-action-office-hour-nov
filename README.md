## Deep-dive path for update #2

1. Inspect `.github/workflows/repo-status.md`: natural-language goal,
   event trigger, permission boundary, tools, network and safe-output limit.
2. Compare it with `.github/workflows/repo-status.lock.yml`, generated by
   `gh aw compile`. This is the executable Actions workflow, not `actions.lock`.
3. Inspect the compiled job permissions and pinned component manifest.
   The agent does not receive write permission; a separate safe-output job
   can create at most one issue.
4. Run `02 - Agentic workflow preflight`, then `Repo status office hour`.
   Review the Actions summary, workflow logs and generated issue.
5. Connect safeguards to the actual run: read-only repository access,
   sandbox/firewall, threat detection, secret handling, and bounded output.

The lockfile presentation segment demonstrates the different
`.github/workflows/actions.lock`: it pins action dependencies to commits.
The Agentic Workflows `*.lock.yml` is generated Actions YAML. They solve
different problems and are both reviewed and committed here.

The repo also contains demonstrations for the prior session's other topics.

revamped presentation.

## Agent authentication

The Copilot engine requires a Copilot license. Create a fine-grained personal
access token with the **Copilot Requests: Read** account permission; no
repository-content permissions are required for that token. An owner must save
it as the repository secret `COPILOT_GITHUB_TOKEN` through
**Settings > Secrets and variables > Actions**. Follow the official
[quickstart](https://github.github.com/gh-aw/setup/quick-start/) and
[authentication reference](https://github.github.com/gh-aw/reference/auth/#github-copilot-default).
Do not paste tokens into source, chat, logs or issues.

The implementation uses the secret-based path. Organization-centralized Copilot
billing is an alternative requiring different permissions and an organization
subscription; it is not implicitly configured in this personal repository.
Check AI and Actions budgets before running. Workflows are manual, not scheduled.
The agent can read this demo repository and request one issue through safe
outputs; it cannot edit code or merge PRs.
